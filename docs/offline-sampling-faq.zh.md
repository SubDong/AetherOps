# 离线采集常见问题

[English](./offline-sampling-faq.md) · **简体中文**

这一页只讲一个开关：`metrics.offlineSampling`。每分钟一次的采集器有两条到达主机的路 —— 走别人已经开着的
终端（一直如此），或者按保存的连接自己拨号（就是这个开关，默认关）。下面四个问题都是开启之前会问到的，
每个答案写的是采集器**实际在做什么**，而不是它应该给人什么感觉。

- [采不到的主机为什么不会每分钟重试](#采不到的主机为什么不会每分钟重试)
- [怎么用 sampling 退出采集](#怎么用-sampling-退出采集)

## 为什么默认是关的

因为打开它改变的是「产品对一台没人在看的机器做了什么」。

开关关着的时候，采集器只读那些已经开着会话的主机：它在你在用的那条连接上多开一个 `exec` 通道，
**从不自己发起登录**。这也是为什么「你连了三分钟，它就正好有三分钟历史」，以及为什么闲置主机留下的是一段空白，
而不是一排 0。

打开之后，没有会话的主机会**每分钟建立一次 TCP 连接、完整地登录一次**。在目标机上，这就是 `sshd` 认证日志里
每分钟一条记录，而且凌晨三点大家都在睡觉的时候照样出现。那是目标机审计轨迹里一处可见的变化，往往还是
「谁在什么时候登录过」的唯一记录。这种事不该由一次升级替你决定：一个认为「这东西只在我开终端时才连」的运维
人员，看到一条自己没要求过的登录记录，理应是惊讶的。所以默认关、开关写进配置文档、是否开启由部署方决定。

在 `~/.aetherops/config.json`（数据目录下，权限 `0600`）里打开：

```json
{
  "metrics": {
    "offlineSampling": true
  }
}
```

或者导出 `AETHEROPS_METRICS_OFFLINE_SAMPLING=1`，环境变量优先于文件。取值在进程启动时读一次（`loadConfig`
会缓存合并后的结果），所以**必须重启** —— 在跑着的服务下面改文件不会生效。`AETHEROPS_METRICS_OFFLINE_SAMPLING`
是一个小范围灰度用的旋钮：写进某一台实例的 unit 文件里，其余的不动。

每台主机每分钟的代价是：一次握手（上限 12 秒）、2 到 4 条共用这条连接的 `exec` 命令、以及
`host_metrics_minute` 里的一行。最多 2 台并行，一轮 45 秒后不再接新活，所以在 50 个连接上打开并不等于
50 个登录同时发生 —— 见第三个问题。

每分钟的候选是什么 —— 所有账号的所有连接，减去：

- `__local__`：没有配置行可拨的虚拟连接，它的历史只能来自某个真的被打开的本地 shell；
- `sampling` 为 `skip` 的连接（第四个问题）；
- 此刻有活会话的主机 —— 它们已经被会话路径采过了，两条路都走会让样本数和登录次数都翻倍；
- 这一分钟已经写过行的、还在退避期里的、以及首次相位还没到的主机。

`local` 类型的连接仍然在候选里，但它是通过 Node 的 `os` / `statfs` 直接读的 —— 不拨号、不登录、不过
「默认服务器 Shell」的口令门禁 —— 所以一轮扫到它就会采。

## 跳板机连接到底采的是哪台机器

`connection.host` —— AetherOps 实际登录进去的那台机器，对跳板机连接来说就是跳板机本身，不是启动脚本要跳过去的
那台。

原因是结构性的，不是图省事：`startupScript` 是 PTY 打开约 800 毫秒后写进**交互式** shell 的一行文本。一次性通道
既没有 PTY、也没有交互式 shell，所以脚本在那里是被**刻意**跳过的。硬在那个通道上跑一次跳转，要么什么也不做，
要么让采集去读跳转过程打印回来的东西 —— 无论哪种，样本都会假装在描述一台它根本没碰过的机器。所以一次性通道采的
就是 `host` 解析到的那台。

这与另外两处早就这样的功能一致：状态面板走直连 SSH 通道探测，文件管理器浏览的也是同一条通道 —— 两者描述的都是
跳板机。这类连接上的活会话同样是从跳板机采的（`execReadonly` 落在同一条直连通道上），这正是两条路的历史能对上的
原因：同一台机器、同一套数字，不存在「你开终端之前」和「之后」之间的接缝。

需要目标机的独立历史，别想办法让采集器跟着跳 —— 而是按目标各建一个连接，用真正的 `-J` / `ProxyJump` 方式。
那种连接是真的在目标机上终止的，于是面板、文件管理器、指标历史和 AI 的环境上下文描述的才是同一台机器。
启动脚本那一跳的存在意义是给你一个落在目标机上的交互式 shell，它从来都不是历史数据的来源机制。

## 采不到的主机为什么不会每分钟重试

因为每分钟失败一次的登录，正是 `fail2ban` 会封掉的东西 —— 而封的是这个 IP，连带别人正开着的终端一起断，
不止是少了几个样本。退避比事故便宜。

这些限制按生效顺序排列：

| 限制 | 取值 | 它挡住的是什么 |
|------|------|----------------|
| 首次相位 | `owner:connection` 哈希 → 0~59.999 秒 | 开关一打开，所有主机在同一秒齐发登录 |
| 分钟去抖 | 每个归属 / 连接 / 分钟只写一次 | 同一个分钟桶里出现两个样本 |
| 并发 | 2 个 worker | 50 台主机同时握手 |
| 单轮预算 | 45 秒后不再接新活 | 一轮拖进下一轮 |
| 轮转游标 | 被预算挤掉的主机下一轮排最前 | 候选多过一轮容量时尾部永远轮不到 |
| 握手上限 | 12 秒（`readyTimeout`），外加 3 秒兜底 | 一台死掉的主机吃掉整轮 |
| 退避（普通） | 1 → 2 → 4 → 8 → 15 分钟，之后停在 15 | 一台挂着的主机每分钟被敲一次 |
| 退避（认证失败） | 30 → 30 → 60 分钟，之后停在 60 | 被 `fail2ban` 把 IP 关掉 |
| 日志节流 | 每台连接 10 分钟最多一条 | 密码填错把 `server.log` 刷满 |

「认证失败」是按错误文本识别的（`authentication`、`permission denied`、`no supported authentication`），
单独一档阶梯，因为它是唯一一种影响面超出「少几个样本」的失败：同一个 IP 还在服务所有人的终端。

算作失败的情形：握手报错或超时；系统家族识别不出来（`unknown`）；或者脚本跑了但什么都没解析出来 —— 远端 shell
不认识脚本里的命令、账号读不到系统信息，这些是失败，而不是一行 0。这几种情况都不会写行，于是 `query_metrics`
报告的是那段时间的空白，而不是把一个假的 0 平均进当天。

恢复是立刻的：第一次成功就把失败次数和重试时刻一起清掉，所以恢复的主机马上回到每分钟一次，不需要爬坡。
隔了很久才回来的那个样本也不会拿旧基线做差 —— 上一次采样只保留 5 分钟，所以中断之后那一分钟的 CPU 在累计口径的
家族（Linux / macOS / 鸿蒙）上存 `NULL`，而不是按整段空窗平均；Windows 报的是瞬时值，照原样存。

重试状态存在内存里：重启服务会清掉所有退避，而重启后的第一轮由上面的相位表错开。这是刻意的 —— 重启通常也意味着
改过配置，新配置应该给每台主机一次诚实的机会。

## 怎么用 sampling 退出采集

开关是全局的，`skip` 是连接级的例外。它存在的原因很具体：你最不希望被无人值守登录的那些机器 —— 生产库、客户环境、
有审计要求的主机 —— 恰恰就躺在连接列表里。没有它，唯一的选择是把全局开关关掉，让所有机器一起失去历史。

列是 `connections.sampling`（迁移 `0008-connection-sampling`），两个取值：

| 值 | 含义 |
|----|------|
| `''`（默认） | 跟随 `metrics.offlineSampling` |
| `skip` | 无人值守时永不拨号这个连接 |

它**不会**做的事：有人开着终端时照样采（那条路是这个功能本身，不是例外）、不会删掉已经存下的行、也不会拦住打开终端、
测试连接或状态面板。它只是一句关于「无人值守登录」的声明。

三种设法，按优先级：连接表单、接口、直接改库。

**1. 连接编辑器**。在表单里展开「离线采集」，选「跳过（不主动采集这台）」。这样标过的连接会在连接列表上
带一枚 `跳过采集` 小标签，例外状态就摆在那里，而不是藏在某一列里。改回「跟随全局设置」即取消标记。

**2. 接口**（编辑器发的就是这个）；只改你传的字段：

```bash
curl -sS -X POST http://127.0.0.1:9802/api/connection/updateConnection \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"id": "<connection id>", "sampling": "skip"}'
```

**3. 直接改库**，当账号用不了界面也调不了接口时：

```sql
-- 连接是按归属隔离的，所以 WHERE 里要带 owner_id
UPDATE connections SET sampling = 'skip'
 WHERE owner_id = '<owner id>' AND id = '<connection id>';

-- 确认
SELECT id, name, host, sampling FROM connections ORDER BY owner_id, id;
```

接口需要一个带 `connections` 权限的账号，而且只改你传的字段 —— 其它字段（包括加密后的密码）原样带过去。
SQL 那条绕过了服务层：对一个普通 `VARCHAR` 列来说无妨，但同时也绕过了名称判重，所以请只改这一列。
（两条路都不会把连接改动写进审计 —— 审计轨迹覆盖的是命令、AI 调用与文件传输。）

生效在**下一轮**，不用重启：候选列表每分钟都从 MySQL 重新读。所以在线改是安全的，取消也一样便宜。

取消它：在表单里选回「跟随全局设置」，或者显式传一次 `"sampling": ""`（或 `null`）。
表单现在总会带上这个字段（`skip` 或 `""`），所以把下拉选回「跟随全局」再保存，确实会清掉通过接口或 SQL
设的标记 —— 这是表单会覆盖这一列的唯一场景；不带这个字段的客户端依旧原样保留，否则「别的工具改一下连接，
标记就没了」这种事查都不知道从哪查起。

顺带两件值得知道的事：

- 标记不跨删除/重建：新建的连接从 `''` 开始。
- `local` 连接也可以带 `skip`，但本来就没有东西去拨它，所以它只是让本该从 Node 计数器写出的那一行不再写入。
